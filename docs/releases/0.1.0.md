First release of the Rust client library backed by Chromium 154.0.8037.49.

### Included

- Naive proxy TCP streams over HTTP/2 and HTTP/3, with authentication, padding,
  connection reuse and directional close.
- Direct native TLS, HTTP/1.1, HTTP/2, HTTP/3 and WebSocket clients. Direct client
  APIs do not route through the Naive proxy.
- Client-local trust anchors and asynchronous certificate verification callbacks.
- Static or DNS-discovered ECH configuration, including per-host direct-client
  policies and strict negotiation mode.
- Runtime-independent futures, optional Tokio/futures-io adapters, owned buffers,
  and monoio/compio integration.
- Native SDK archives with public C headers, manifests, license notices and
  checksums. The Rust wrapper requires native ABI 6 from this release.

### Installation

Use the Rust workspace from tag `v0.1.0` and the native archive for the matching
target. Install the archive with `cargo xtask fetch --target <triple> --url <url>
--sha256 <checksum>`, or build it using `cargo xtask toolchain` and
`cargo xtask build`. Ordinary Cargo builds do not download Chromium automatically.
This release distributes source and native SDKs through GitHub; it does not
publish crates to crates.io.
The core and monoio adapter require Rust 1.85 or newer; the compio adapter
requires Rust 1.93 or newer.

See the repository's `docs/native-distribution.md`, `docs/platforms.md`,
`docs/browser-client.md` and `docs/tls-policy.md` for integration and API details.

### Scope and validation

The release matrix builds and links the listed native targets before publishing
the archives. Cross-compilation is not device or application runtime testing.
Local macOS arm64 validation includes 125 repeated browser/security test
executions, 100 server-confirmed successful ECH handshakes and 96 Naive regression
executions. The committed validation reports record the exact source and native
archive hashes and their limitations.

HTTP uploads currently use an owned in-memory body, limited to 64 MiB. WebSocket
messages and response collection have explicit bounds. The crate does not expose
general UDP forwarding or a server/listener API. Chromium-native networking does
not constitute a verified claim of complete Chrome fingerprint equivalence.
